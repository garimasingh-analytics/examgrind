# Tracking Audit: 2026-08-20

**Codebase:** ExamGrind  
**SDK:** GA4 `gtag.js`, Google Ads conversion helper, Meta Pixel helper

## Current Tracking Inventory

The codebase defines and calls 40 typed GA4 product events through `lib/product-analytics.ts`. The inventory in [`../current-state.yaml`](../current-state.yaml) records every event, its current live call site, properties, and browser source.

The main visitor sequence has live calls for `landing_book_opened`, `landing_cta_clicked`, `landing_exam_selected`, `diagnosis_started`, `diagnosis_question_answered`, `diagnosis_completed`, `diagnosis_result_viewed`, `diagnosis_signup_clicked`, `diagnosis_signup_completed`, and downstream handoff actions.

The scan found that `landing_book_opened` was defined but had no call site before this audit. It is now emitted once when `CinematicLanding` mounts. All 40 defined product events have a live call site in the scanned codebase after that change.

## Identity Management

| Call type | Present | Details |
|---|---|---|
| `identify()` | No | No GA4 user ID, email, name, or traits are sent. |
| `group()` | No | ExamGrind is B2C and has no group hierarchy. |
| `page()` / screen | GA4 default config | The Google tag configures page measurement after consent. |
| reset / logout | No | No browser analytics identity is set. |

## Observed Patterns

- **Naming:** snake_case event names with action/object phrasing.
- **Call routing:** Product events are routed through one typed browser wrapper. Google Ads and Meta conversion calls use focused helpers.
- **Consent:** `MarketingTracking` initializes denied consent, enables tags only after analytics/ads consent, and the product wrapper returns without sending when consent is not granted.
- **Delivery:** Browser event calls are non-blocking. No quiz answers, typed Coach topics, payment identifiers, emails, or names are passed to the GA4 product wrapper.
